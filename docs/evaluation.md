# Evaluation

This repository contains metric implementations and evaluation instructions. **It does not currently contain benchmark results from real meeting recordings.** The offline fixture demo below exists to show how the metrics are calculated without private recordings, model downloads, or API credentials.

## 1. Offline synthetic demonstration

Run from the repository root:

```bash
python scripts/run_synthetic_evaluation.py
```

The command reads the hand-written fixtures in [`examples/synthetic_evaluation/`](../examples/synthetic_evaluation/). It does not load Whisper, pyannote, an LLM, an embedding model, or Qdrant; the retrieval ranking is manually specified. The numbers below are therefore **synthetic calculation examples, not system-performance results**.

| Metric | Synthetic demo value | Fixture size | What it demonstrates |
|---|---:|---:|---|
| WER | 7.25% | 1 toy transcript pair | Text normalization and edit-distance calculation |
| Recall@1 | 40.00% | 5 toy queries | Relevant item ranked first |
| Recall@3 | 80.00% | 5 toy queries | At least one relevant item in top 3 |
| Recall@5 | 100.00% | 5 toy queries | At least one relevant item in top 5 |
| Action-item precision | 75.00% | 4 predicted items | Share of predicted items matched to the toy gold list |
| Action-item recall | 75.00% | 4 gold items | Share of toy gold items recovered |
| Action-item F1 | 75.00% | 1 toy meeting/action list | Harmonic mean of toy precision and recall |

**Important:** these values are computed from manually written examples. They were not generated by Whisper, pyannote, the configured LLM, an embedding model, or Qdrant. Do not put them in a CV, paper, presentation, or project description as measured model performance. The small fixture counts are not statistically meaningful.

DER and real-time factor (RTF) are intentionally not assigned synthetic values here. DER requires annotated reference speaker turns and the diarization system's predicted turns; RTF requires timing an actual audio-processing run on stated hardware. Neither can be inferred from the text fixtures.

## 2. Real evaluation methodology

Use recordings that you have permission to process. Keep the audio, transcripts, annotations, and outputs private unless they are licensed for redistribution and appropriately anonymized. Do not commit private meeting data to this repository.

| Metric | How to measure | Command / tool |
|---|---|---|
| **WER** (ASR) | Create a manually corrected reference transcript for each held-out recording. Compare it with the system transcript. | `meeting-intel wer reference.txt hypothesis.txt` |
| **Search quality** | Write 20–30 questions over the indexed meetings and list the relevant `(meeting_id, chunk_id)` for each question. | `meeting-intel eval-search questions.json -k 3` |
| **Action items** | Create a manually reviewed gold list and compare it with the model's extracted items. Both inputs are JSON lists of strings. | `meeting-intel eval-items predicted.json gold.json` |
| **DER** (diarization) | Hand-label speaker turns and compare them with the pyannote output. | `pyannote.metrics.diarization.DiarizationErrorRate` (external dependency) |
| **RTF** (speed) | Divide wall-clock processing time by audio duration. Record CPU/GPU, model sizes, and whether model loading is included. | Time a real `meeting-intel process` run |

Example question-set format: [`examples/search_questions.example.json`](../examples/search_questions.example.json). The example file is a template; replace its placeholder meeting IDs and relevance labels with IDs and labels from your own indexed dataset before running `eval-search`.

### Metric interpretation and caveats

- **WER implementation:** the bundled function lower-cases, removes punctuation, Unicode-normalizes, splits on whitespace, and computes edit distance. For Vietnamese, whitespace tokens are not necessarily linguistically segmented words. Treat this as a whitespace-token error rate unless you apply a consistent Vietnamese word-segmentation procedure to both reference and hypothesis. Character error rate (CER) may be more appropriate for some Vietnamese evaluations.
- **Action-item matching:** the current implementation uses greedy one-to-one matching based on word-set Jaccard overlap (threshold 0.4). It is a simple proxy, not a semantic judge; manually review borderline matches and consider stricter field-level evaluation for task, owner, and deadline.
- **Recall@k:** a query is counted as solved when any relevant chunk appears in its top-k results. It does not measure answer correctness or ranking quality beyond that hit criterion. Consider adding MRR or nDCG for a fuller retrieval evaluation.
- **DER:** use the same collar, overlap, and speaker-mapping conventions across experiments and report them with the result.
- **RTF:** state the hardware, batch size, audio duration, model versions, and whether cold-start/model-loading time is included.
